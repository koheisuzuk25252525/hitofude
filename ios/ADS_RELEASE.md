# 広告の公開手順

## 実装
- Google Mobile Ads 12.14.0、UMP 3.1.0（固定）。通常ゲーム表示後に毎回UMPの情報を更新。広告SDKは道案内を選び、同意フォームを必要に応じて表示して `canRequestAds` を確認した後だけ起動。
- 更新・フォームの失敗時は広告を要求しない。ゲームは継続でき、報酬は付与しない。
- 「…」→「広告のプライバシー設定」で再選択。メニューを閉じてから表示し、ゲーム時間を停止。対象外の地域ではその旨を案内。
- 常に `npa=1` を要求。ATTを要求せず、IDFAの許可文言も追加しない。非パーソナライズ広告でもデータ処理はあるため、同意確認を省略しない。
- アプリID: `ca-app-pub-2673589317149443~3945033649`（UMPもこのアプリの設定を取得する）
- 本番ユニット: `ca-app-pub-2673589317149443/7093941165`
- Debugは常にGoogle公式テストユニット。ReleaseもStoreKitの検証済みAppTransactionがproductionのときだけ本番ユニットを使用。TestFlight/sandbox/未検証/取得失敗はテストユニット。同じアーカイブをTestFlightから正式配布へ進められる。

## 管理画面と公開順序
1. 本PRのポリシーをレビューし、公開サイトへ反映する（PR作成だけでは公開されない）。
2. AdMobの欧州・米国メッセージをレビューして公開する。現在は下書きなので、UMPがフォームを取得できない場合がある。
3. 以下の実機確認を行う。Debug/TestFlightで本番広告を自己視聴しない。
4. App Storeのプライバシー回答を実際のSDK・配信設定と照合。Google公式のiOSデータ開示資料とArchiveのPrivacy Reportを利用する。デバイス識別子・概略位置・広告/製品操作・診断情報、第三者広告/分析目的、リンクの有無を確認。非パーソナライズという理由だけで「収集なし」としない。
5. App Store掲載のデベロッパWebサイトのホスト直下に `app-ads.txt` を公開する。内容は `google.com, pub-2673589317149443, DIRECT, f08c47fec0942fa0`。GitHub Pagesの `/hitofude/app-ads.txt` ではホスト直下にならないので、このリポジトリに置くだけで完了としない。ユーザーサイト用リポジトリまたは独自ドメインを準備する。
6. 公開後AdMobにストア情報を紐づけ、アプリ審査・app-ads.txtの検証状況を確認。

## 実機チェック
- 初回/再起動、同意する/拒否する/設定変更、通信不可、フォーム読み込み失敗、バックグラウンド復帰。
- 同意前に広告SDKが開始されないこと。拒否した場合でも通常ゲームが続けられること。canRequestAdsは「全目的に同意した」という意味ではなく、UMPが許可する範囲の広告要求可否。
- 道案内前の同意フォーム表示中はタイマー停止。広告途中閉じ/読み込みキャンセル/失敗で報酬なし。完了だけ1区間。
- 「広告のプライバシー設定」が対象地域で再選択画面を開くこと。
- EEA/米国はUMP DebugSettingsのテスト端末とgeographyを開発ビルドだけに指定して確認する。本番へ強制地域やreset処理を含めない。
- TestFlightでもテスト広告ラベルを確認。正式配布時のStoreKit環境判定は実配布で最終確認する。
