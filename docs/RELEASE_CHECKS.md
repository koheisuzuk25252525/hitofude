# 公開前の品質チェック

## 互換性と今回の変更

- 問題生成のアルゴリズムと乱数消費順は変更していない。シード互換テストで変更前mainの経路・手がかりを比較する。
- `hitofude:` で始まるlocalStorageのキー・値の形式は維持する。0ミリ秒の記録も記録ありとして扱う。
- 対戦URL `#c-<e|m|h|d|o>-<seed>-<秒>` と秒への四捨五入は維持する。
- クリア時にミリ秒の記録を確定し、ベスト・今日の結果の保存、結果コピー、挑戦リンクで同じ記録を使う。再度finishが呼ばれても確定値を変えない。次の問題でリセットする。
- 毎日の問題の共有日付は、その問題のseedの日付に合わせる。
- ヘッダーはタイトルとステータスの2段。375〜430pxでは操作ボタンは2列、480px以上は4列。タップ領域は44px以上を基本にし、盤面は枠込みの幅にする。
- `fitBoard()` の高さによる説明省略は `#instructions` のみが対象。カレンダー内の説明は省略しない。
- 指の実際の線分を1マスの1/4以下の間隔で補間し、取得できる場合はcoalesced pointer eventsも処理する。斜め移動・不正な数字・再訪問の判定は既存のtryStepに委ねる。盤面外やpointercancel／lostpointercaptureで線分を切る。
- 鬼の生成はWorkerで実施し、20秒のタイムアウト・error・messageerror・生成開始失敗で読み込み表示を閉じる。同じseedで再試行するか、ふつうへ移れる。メインスレッドでの8×8生成への切り替えは行わない。別の問題への切り替えは古いWorkerを終了し、古い結果・エラーを無視する。

## 制作者と作品一覧

`index.html` の `SITE_CREDITS` に実際の情報を設定する。

```js
const SITE_CREDITS={
  name:'実際に表示する制作者名',
  creatorUrl:'https://example.com/about',
  worksUrl:'https://example.com/works'
};
```

上記URLは説明用の例。現在の設定はすべて空欄で、フッターは非表示。公開時は本物のURLに置き換える。個々の空欄は表示されず、リンクにはHTTPSだけを使う。名前はHTMLではなくテキストとして描画する。

## OGP

- タイトル・説明・正規URL・共有画像の絶対HTTPS URLをHTMLのmetaに設定済み。
- `assets/og-image.png` は1200×630の共有画像。編集用原本は `assets/og-image.svg`。原本を変えた場合はPNGも再出力し、幅・高さを確認する。
- GitHub Pagesで画像がHTTP 200・image/pngとして取得できることをマージ後に確認する。
- SNSのOGPキャッシュにより反映が遅れる場合がある。実際の共有プレビューは公開後に確認する。

## 自動テスト

```sh
node tests/generator.test.mjs
node tests/generator-compatibility.test.mjs
node tests/ui.test.mjs
```

ブラウザテストはNode.js 22以降の組み込みWebSocketとインストール済みChromium／Chromeを使用する。npm依存はない。外部フォントをブロックした状態でローカルHTTPサーバーにアクセスし、以下を検証する。

- 375／390／430px、ライト／ダークでヘッダー・タブ・操作ボタン・盤面のはみ出しがない。
- 高速な実touch入力、逆戻り、斜め拒否、盤面外への離脱、coalesced events、キャンセル、チュートリアルの完了。
- クリア24時間後もコピー文面・リンク・確定タイムが同一。日付seedと保存記録も一致する。
- Workerのerror／messageerror／コンストラクタ失敗／タイムアウトと再試行、生成中のモード変更。
- 保存済みベスト・効果音／音声設定、チュートリアル完了、daily記録、既存対戦URL。
- 制作者設定の空欄・HTTPS制限、OGP画像の配信、未処理のブラウザ例外がないこと。

GitHub Actionsのpagesワークフローでも実行する。Chromiumの結果はiPhone Safariの動作保証ではない。

## Safariでのページ移動対策

html/bodyは常時固定し、ドキュメント全体がスクロールしない構造にする。短い画面では `#appScroll` の中だけをスクロールできる。盤面のタッチ操作中はその内部スクロールも固定し、documentのcapture段階に置いた非passiveのtouchstart／touchmoveでパンを抑止する。pointerup／pointercancel／lostpointercapture、画面非表示・フォーカス喪失、新しい問題で固定を解除し内部のスクロール位置を戻す。盤面外の操作や、クリア画面・エラー画面のボタンは通常の操作のまま。

ブラウザ回帰テストは、内部スクロールした位置からの入力、盤面位置の維持、touchmoveの取り消し、終了・キャンセル・フォーカス喪失・モード変更での解除と、document自体が移動しないことを検証する。SafariのブラウザUIの伸縮や、埋め込み元ページ自体の移動は制御範囲外なので、実際に使う画面で再確認する。

読み上げはすべて日本語（ja-JP）。音声オフ設定のキーはそのままで維持する。


## ヒントの確認

ヒント1回で、間違った経路があれば正しい接頭部まで戻し、次の1マスを黄色の枠と通過順の数字で示す。目印と説明は実際に進む／取り消す／やり直す／問題を切り替えるまで残す。目印表示中はヒントボタンを無効にし、同じ目印で複数回消費しない。3回目の目印も回数が0になった後まで残す。必要なら対象のマスを表示領域へスクロールする。

自動テストは最初のマス、正しい経路、合法だが間違った分岐の修正と次のマスの同時提示、重複消費防止、別のアニメーション終了、視差効果を減らす設定、3回目、練習での消費禁止を検証する。実機では、小さい画面でヒント対象と説明が見えるか・進むと消えるかを確認する。

## 短い時間で一問を楽しむ

- 初回は従来のチュートリアル。練習後・通常の再訪時は「やさしい」を直接開始する。対戦URLは引き続き指定された難易度・seed・相手の記録を優先する。「きょうの1問」はタブから選べる。
- 開始位置に「ここから」、プレイ中は次の手がかりの数字と残りの歩数を表示する。参照するのは公開済みの手がかりと現在の歩数だけで、正解経路を示す機能ではない。取り消し・ヒントで経路が戻った際にも更新する。
- クリア時は実際の自己ベスト更新やヒント利用に応じた一言を表示。「もう一問」を主ボタンにし、完了後に不要なプレイ用操作を隠す。ミス数の集計と共有結果の形式は従来どおり保持する。
- 「完成した線を見る」で盤面を眺められる。「結果に戻る」で共有操作に戻り、「もう一問」で次の問題へ進める。鑑賞中の操作では経路・確定タイム・保存記録を変更しない。
- 視差効果を減らす設定では紙吹雪と結果の登場アニメーションを止める。次の問題では前の紙吹雪・遅延演出を残さない。
- カレンダーの達成日と結果オーバーレイのCSSクラスを分け、達成日が見えなくなる干渉を解消する。

自動テストでは上記の遷移、初回／再訪／旧対戦リンク、0ミリ秒のベスト保持、375／390／430pxのライト・ダークで結果と鑑賞画面の収まりを確認する。`UI_SCREENSHOT_DIR` を指定すると開始・結果・鑑賞の画像を出力する。

実機では、次の数字の案内が指なぞりを邪魔しないか、クリア→鑑賞→結果→共有の流れと、短い画面・文字拡大で操作できるかを確認する。遊びたくなるかどうかは自動テストでは判断できないため、「一問終えて気持ちよかったか」「次に暇になったら開きたいか」をテストプレイヤーに聞く。
