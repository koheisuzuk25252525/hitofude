# 公開時に行う作業

## 審査へ送る前

1. App Store Connect のApp Store向けバージョン1.0に、既存の **ビルド6** を選ぶ。
2. `store-listing-ja.txt` の文面とスクリーンショットを登録する。説明文と画像は現在のアプリの内容に合わせる。
3. `privacy-audit.md` を使ってAppのプライバシーを照合し、実際の年齢区分質問票、価格・配信地域、審査連絡先、暗号化の項目を確認する。
4. 審査メモは `review-notes-en.txt` または `review-notes-ja.txt` を貼り付ける。ログイン用アカウントは不要。
5. 実機確認で重大な不具合がなく、画面の必須項目が揃ったら審査へ提出する。この資料作成では提出操作はしていない。

公開方法・審査設定は変更していません。現在の指定に従って進めます。警告修正 `5086f9a` のためだけに初回公開ビルドを差し替えたり、自動TestFlight配信を有効にしたりする必要はありません。

## App Storeページを実際に開けるようになったら

### 手紙からインストールする入口

公開したアプリの実際のApp Store URLを確認して、Web版 `letter-links.js` の `appStoreURL` に設定します。現在は空欄で、架空のインストール先は表示しない設計です。

- 正しいApp Storeのアプリ名・開発者・アイコンかを確認する。
- Web側だけの変更なので、これを理由にアプリを再アップロードする必要はない。
- 更新はその時点のWeb用の別ブランチで確認してから行う。本作業ではmainに変更していない。
- 未インストール端末で手紙を開き、ストアへ移動できることを確認する。
- インストール後は元の手紙リンクをもう一度開く。インストール後の自動引き継ぎは実装されていない。

### AdMobの登録

AdMobのヒトフデに、公開したiOSアプリのストア情報を紐づけます。アプリ審査と `app-ads.txt` の認識状況は管理画面で確認します。

ホスト直下の公開元には既に次の行があります。

```text
google.com, pub-2673589317149443, DIRECT, f08c47fec0942fa0
```

URL：`https://koheisuzuk25252525.github.io/app-ads.txt`

App StoreのデベロッパWebサイトとこのホストの対応を確認します。本作業ではAdMobの管理設定・広告メッセージ・公開状態は変更していません。

## 公開後の確認

- 通常プレイを一問、保存・復帰、手紙リンクを確認する。
- サポートメール、ストアレビュー、App Store Connectのクラッシュ・利用状況を確認する。
- 利用者の報告は、端末・OS・アプリのバージョン・再現手順と合わせて記録する。
- 初回は「起動できない」「遊べない」「記録が消える」「広告から戻れない」を優先する。

問い合わせ先の新設や計測機能の増設を、この初回公開の前提にはしません。
