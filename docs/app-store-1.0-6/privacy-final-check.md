# プライバシー申告を確定する最後の確認

今回取得した公式SDKの宣言では、Google Mobile Ads 12.14.0のデバイスIDに「トラッキングに使用」が含まれます。ヒトフデのコードは非パーソナライズ広告を要求し、ATTの許可要求は実装していません。**SDKの汎用的な宣言と、このアプリが実際に使う設定・データ処理を照合してから申告します。** この宣言だけでアプリの不具合や再提出が必要だと決めたものではありません。

## まず確認する画面

1. MacのXcodeで **Window → Organizer → Archives** を開く。
2. 実際にTestFlightへアップロードした **Version 1.0 / Build 6** のArchiveを選ぶ。今回の警告修正や撮影用ビルドは使わない。
3. Archiveのメニューから **Generate Privacy Report** を使って、SDKも含めたレポートを出す。Xcodeの版によって項目の場所が違う場合は、Archiveを選択した状態のメニューを確認する。
4. App Store Connectの「Appのプライバシー」に入力済みの回答と、AdMob側で実際に使っている配信・同意設定を確認する。

レポートだけでも実行時のすべてのデータ利用は確定しません。`privacy-audit.md` の公式SDK宣言・実装根拠と合わせて照合します。APIキー・証明書・Appleのパスワードを共有する必要はありません。

## 確認する内容

- デバイスID、製品の操作、おおよその位置情報、広告データ、診断などの実際の収集項目。
- それぞれの目的、利用者への関連付け、Appleの定義におけるトラッキングの有無。
- 任意のFirebase計測がビルド6で利用可能になっているか。設定ファイルの有無はリポジトリだけでは分からないため、実際のArchiveで確認する。
- 非パーソナライズの指定やATT要求がないことだけで、全SDKを「収集なし／トラッキングなし」としていないか。

SDKマニフェストと申告に差がある場合は、その理由を実際の設定・データ利用から確認します。実装の変更が必要と分かった場合に限り、新しいビルドが必要かを判断します。公開用1.0（6）は現時点で変更していません。
